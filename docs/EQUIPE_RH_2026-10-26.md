# Equipe institucional para a conta de RH

Continuação da [Issue #12](https://github.com/Fixa-Inter/segundo-aplicacao-website/issues/12), na branch feature/integracao-ia-manu. O usuário forneceu uma conta de RH para validar a integração publicada, com expectativa de visualizar técnicos e gestores da própria instituição. Nenhuma credencial foi incluída neste registro.

## Contrato e diagnóstico

- O login real retornou HTTP 200 e tipo ADMINISTRADOR. O contrato atual não possui um tipo RH separado.
- A listagem anterior da Web sempre filtrava TECNICO e, para administrador, limitava os resultados à unidade do CNPJ. Por isso não atendia à visão institucional solicitada.
- A API fornece unidadeId no próprio usuário e instituicaoId nas unidades. A Web identifica a instituição pelo vínculo do usuário consultado no servidor, sem usar o CNPJ salvo como autoridade para escolher outra instituição.
- As consultas de equipe são enviadas por unidadeId, somente para unidades da instituição identificada. A resposta é filtrada por unidade e pelos tipos GESTOR e TECNICO. Se a instituição não puder ser confirmada ou a API negar a consulta, a tela não tenta uma listagem global.

O contrato foi conferido no código da API em dev, commit [8e02b32](https://github.com/Fixa-Inter/segundo-api-web/tree/8e02b32b517f4e5b10e674681661161d695225e2), e nas respostas reais da AWS. Não houve alteração no backend.

## Alterações na Web

- A equipe institucional mostra técnicos e gestores, com unidade, tipo de acesso, busca, filtros e paginação.
- Gestores têm detalhes informativos com o papel real; competências, desempenho e ações do formulário técnico permanecem exclusivos dos técnicos.
- A edição de técnico de outra unidade da mesma instituição carrega seus turnos e preserva a unidade e o endereço. A criação continua exclusivamente de técnicos, vinculada à unidade da conta.
- O fluxo do gestor permanece restrito aos técnicos de sua unidade, com escopo aplicado pelo servidor e sem consultar a listagem administrativa de unidades.
- O perfil exibe Administrador quando esse é o tipo de acesso retornado, em vez de rotular toda conta como Gestor.

As respostas autenticadas foram comparadas aos IDs apresentados na paginação, sem publicar nomes ou identificadores pessoais.

- Paginação e filtros de tipo de acesso/unidade passaram. Detalhes de gestor abriram sem competências, desempenho técnico ou ação de edição técnica.

## Pendência no contrato de autorização da API

O servidor trata ADMINISTRADOR como acesso global: as consultas de usuários e unidades podem retornar registros de outras instituições. O ajuste da Web limita a exibição da equipe, mas não é uma barreira de autorização do servidor.

Se esta conta representa um RH que deve acessar somente sua instituição, a equipe da API precisa aplicar esse vínculo na autorização das consultas e alterações ou distinguir RH de administrador global. A Web não alterou esse contrato. O diagnóstico não avalia nem corrige os demais endpoints globais do administrador.
